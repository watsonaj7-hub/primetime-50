## Date policy

Group by `performed_at` converted into that row's valid stored `record_timezone`. Keys are ISO calendar day plus the explicit stored zone. Never use the host/browser's implicit locale or current timezone. Within groups, records sort by instant descending then UUID descending using binary lexical comparison. PostgreSQL microseconds are retained for ordering rather than reduced to JavaScript millisecond ties. Groups appear in the order of their newest member; different zones are distinct groups, so grouped order need not be a single interleaved global timeline. Session and completion times display seconds, explicit GMT offset and stored zone using `en-AU` formatting; original ISO instants remain the HTML `time` values. A DST offset can legitimately differ between performed and completion times. Invalid or missing dates/zones are errors, without UTC/device-zone substitution.

## Conservative strength rules

This is descriptive observed load evidence, not clinical readiness, progression, estimated 1RM, a universal strength percentage or an all-time personal best. It uses only the latest **100 completed owned records** returned by the server. No broader-history claim is made even when fewer than 100 are returned.

A comparison requires at least two distinct completed sessions with the exact same reviewed catalogue UUID, content ID/version, rule version, canonical exercise UUID, saved label and observed positive rep count. The immutable reviewed version fixes movement/protocol identity. A display name alone never establishes comparability. Personal records are displayed but excluded from comparison because a caller-chosen key does not establish an immutable protocol. Duration-based prescriptions are excluded: seconds never become reps. Zero reps do not establish comparable rep work. Null values, nonfinite values and inconsistent snapshots never generate metrics.

Within each session/reps series take the maximum actually recorded kg; retain 0 kg. Compare the earliest and latest comparable sessions in the window, not the maximum intervening session. Equal instants use ascending ID for baseline/latest selection. Equal loads are explicitly ties; lower latest loads remain negative differences. Observed difference is exact decimal subtraction of the decoded JSON numeric representations and is returned as a decimal string, including small fractions; no percentage division or invented score. One session, no comparable pair or empty history produces an explicit insufficient-data state. History parsing/canonicalisation leaves the supplied original arrays unchanged.

Home/progress literal weight, waist, step, sleep, recovery, adherence, consistency, streak and habit-completion claims are removed. The former chart is a descriptive comparison list or honest unavailable/insufficient state; it has no fabricated series. Habit analytics are explicitly unavailable. Existing shell, tokens, Card/Button/Input primitives and logger/input remain; only the shell's sample-content notice is narrowed to match actual changed state.
